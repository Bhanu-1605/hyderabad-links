# API specification

OpenAPI is the contract (generated by the API, consumed by `packages/api-client`). Endpoints are added per phase.

| Prefix | Audience | Status |
|---|---|---|
| `/api/v1/public` | anyone | `GET /meta`, `GET /cities`, `GET /cities/{city}/localities`, `GET /categories`, `GET /listings/search?q&city&locality&category&lat&lng&radiusKm&sort&page&pageSize`, `GET /listings/nearby?lat&lng&category&radiusKm&limit`, `GET /listings/{city}/{locality}/{slug}` |
| `/api/v1/auth/owner` | owner login (public) | `POST /otp/request {phone}`, `POST /otp/verify {phone, code}` -> `{accessToken, refreshToken, expiresInSeconds}`, `POST /refresh {refreshToken}`, `POST /logout {refreshToken}` |
| `/api/v1/me` | business owners | `GET /me`; `GET/POST /me/listings`; `GET/PUT /me/listings/{id}`; `POST /me/listings/{id}/submit` (new listings start as `draft`; submit moves them to `pending_review`; an admin approves them in Phase 5) |
| `/api/v1/auth/admin` | admin login (public) | `POST /login {email, password}` -> `{accessToken, refreshToken, expiresInSeconds}`, `POST /refresh {refreshToken}`, `POST /logout {refreshToken}`. Invite-only: there is no sign-up endpoint, and the first account is created by the CLI bootstrap |
| `/api/v1/admin` | administrators | `GET /me`; `GET /listings?status&page&pageSize`; `GET /listings/{id}`; `POST /listings/{id}/approve`; `POST /listings/{id}/reject {reason}` |
| `/api/v1/super-admin` | super-administrators | Phase 7 |
| `/webhooks/razorpay` | Razorpay (signed) | Phase 6 |
| `/health/live` | platform probes | exists |

## `GET /api/v1/public/listings/search`

The directory's one search endpoint. Only `active` listings are ever returned.

| Parameter | Meaning |
|---|---|
| `q` | Business name, service or keyword. Matched against the listing's full-text vector (name weighted above description), against the name by trigram similarity so misspellings still land, and against the category's `search_terms`. Trimmed; cut at 100 characters. |
| `city`, `locality`, `category` | Slugs. A parent category slug also matches its sub-categories. A locality matches listings based there *and* listings that declare it as a service area. |
| `lat`, `lng` | Must be supplied together. Adds `distanceMetres` to every row. |
| `radiusKm` | Only with coordinates. Clamped to 0.1-50. |
| `sort` | `relevance`, `distance` (needs coordinates) or `name`. Defaults to relevance with `q`, distance with coordinates, otherwise name. |
| `page`, `pageSize` | `page` is 1-based; `pageSize` is clamped to 1-50 and defaults to 20. |

Anything unusable answers `400` with a message; out-of-range numbers are clamped rather than refused.

```jsonc
{
  "items": [{
    "slug": "urban-plumbing-services",
    "name": "Urban Plumbing Services",
    "citySlug": "hyderabad", "localitySlug": "beeramguda", "localityName": "Beeramguda",
    "categorySlug": "plumbers", "categoryName": "Plumbers",
    "distanceMetres": 442,          // null unless lat/lng were sent
    "addressLine": "Plot 12", "phonePrimary": "+919876543210", "phoneWhatsapp": null,
    "url": "/hyderabad/beeramguda/plumbers/urban-plumbing-services"
  }],
  "page": 1, "pageSize": 20, "total": 37, "totalPages": 2
}
```

`total` counts every match, not just this page, and is still reported when `page` is past the end
(`items` is then empty) so a client can send the visitor back to page 1.

## `/api/v1/admin/listings` — moderation

Admin tokens carry the audience `admin`, validated by their own authentication scheme, so an owner
token is refused by every route here before any handler runs (and an admin token is refused on
`/api/v1/me`). Nothing about permissions travels in the token: each request reads the caller's roles
and permissions from the database, so disabling an account or removing a role takes effect at once.

| Endpoint | Permission | Behaviour |
|---|---|---|
| `GET /me` | any active admin | The caller's email, display name, roles, and the permissions they hold *on this surface*. Super-admin permissions are never reported here. |
| `GET /listings` | `listings.view` | The queue. `status` is one of `pending_review` (default), `active`, `rejected`, `draft`, `suspended`; anything else answers `400`. `pending_review` is ordered oldest submission first, every other status by most recent change. `page` is 1-based, `pageSize` clamped to 1-50 (default 20). |
| `GET /listings/{id}` | `listings.view` | Everything a reviewer needs: contact details, map point, who submitted it, and the last decision taken. `404` when the listing does not exist. |
| `POST /listings/{id}/approve` | `listings.review` | Sets `active` and stamps `published_at` (a listing that was live before keeps its original date). Clears the rejection note. |
| `POST /listings/{id}/reject` | `listings.review` | Body `{ "reason": "..." }`, 10-1000 characters; shorter answers `400` with a field error. Sets `rejected` and stores the reason for the owner to read. |

Both decisions require the listing to be `pending_review`; anything else answers `409`, which is what
a second reviewer gets when someone has just decided. An admin without the permission gets `403`.

Every approval and rejection writes one row to `audit_logs` (`listing.approved` / `listing.rejected`,
`actor_type = 'admin'`) in the same transaction as the change, so a decision cannot be applied without
being recorded. Sign-ins and failed sign-ins are recorded too (`admin.signed_in`,
`admin.sign_in_failed`, and `admin.session_reuse_detected` when a refresh token is replayed).

```jsonc
// GET /api/v1/admin/listings?status=pending_review
{
  "items": [{
    "id": 42, "name": "Urban Plumbing Services", "status": "pending_review",
    "categoryName": "Plumbers", "localityName": "Beeramguda",
    "addressLine": "Plot 12", "phonePrimary": "+919876543210",
    "createdAt": "2026-10-15T11:21:00+00:00", "updatedAt": "2026-10-15T11:22:00+00:00"
  }],
  "page": 1, "pageSize": 20, "total": 1, "totalPages": 1
}
```

### Creating the first admin

There is no HTTP endpoint for creating an admin (docs/security.md). The first account is created from
the command line, with the password supplied as an environment variable so it stays out of the shell
history and the process list:

```powershell
$env:ADMIN_BOOTSTRAP_PASSWORD = "a long passphrase"
dotnet run --project backend/BusinessDirectory.Api -- create-admin --email you@example.com --name "Your Name" --role super_admin
```
